# To-do app workflows (EXAMPLE DATA, stage 1 input)

Plain-English workflows as a human would write them. An agent reads this file
and produces the candidate machines and the event sequences in stage 2.

1. **Create and complete a task.** I write a new task as a draft, add it to my list, start working on it, and mark it done.
2. **Snooze and resume.** I start a task, snooze it until tomorrow, resume it, and finish it.
3. **Reopen a done task.** I finish a task, then realise it is not really done and reopen it; it goes back to my to-do list.
4. **Archive a done task.** After finishing a task I archive it so it leaves my list but is kept.
5. **Delete a draft.** I start writing a task, change my mind, and delete the draft.
6. **Restore a deleted task.** I add a task, delete it by mistake, and restore it from the trash back to my list.
7. **Complete without starting.** A quick task: I add it and tick it done straight away, without starting it first.
8. **Rule: an unfinished task cannot be archived.** If I start a task and try to archive it before it is done, the app must refuse.
